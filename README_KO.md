# STORYBORN — Unity 전투 프로토타입 v0.1

첨부된 「신규 2D 도트 로그라이크 게임 기획서 v0.1」의 전투 방향을 바탕으로 만든 **첫 플레이용 프로토타입**입니다. 정식 게임의 완성본은 아닙니다. 외부 이미지나 아트 에셋 없이, 런타임에 생성한 사각형으로 구성합니다.

## 실행

1. Unity Hub에서 **Unity 2022.3 LTS**를 설치합니다. 기준 버전은 **2022.3.62f1**입니다.
2. 압축을 푼 뒤 Hub의 **Add → Add project from disk**에서 `Storyborn` 폴더를 선택합니다. `Assets`, `Packages`, `ProjectSettings`가 바로 보이는 폴더입니다.
3. 에디터가 열리면 `Assets/Scenes/Prototype.unity`를 열고 **Play**를 누릅니다. 메뉴 `Storyborn → Open Prototype`으로도 열 수 있습니다.
4. **Game 뷰를 클릭**하고 Enter 또는 시작 버튼을 누릅니다. 16:9 / 1280×720 화면을 권장합니다.

씬은 의도적으로 비어 있습니다. Play를 누르면 `StoryGame.Boot()`가 카메라·지형·캐릭터·UI를 생성합니다. 오브젝트나 프리팹을 수동으로 연결할 필요가 없습니다. Unity 6으로 업그레이드는 별도 검증하지 않았습니다.

## 조작

| 입력 | 동작 |
|---|---|
| A / D 또는 ← / → | 이동 |
| Space | 점프 |
| J 또는 마우스 왼쪽 | 임시 근접 공격 |
| 왼쪽 Shift 또는 K | 무적 대시 |
| 방향키 + 대시 | 지상·공중 8방향 대시. 방향 입력이 없으면 바라보는 방향 |
| E | 적 전멸 후 오른쪽 출구에서 다음 구간으로 진행 |
| 1 / 2 / 3 또는 버튼 | 방 클리어 보상 선택 |
| Esc | 일시정지 / 계속 |
| R | 사망·클리어 화면에서 새 도전 |

## 한 번의 플레이

- 1구간: 근접 돌진형 시험 적 2명.
- 2구간: 근접형 1명 + 원거리형 2명.
- 3구간: 돌진 / 지면 파동 / 투사체를 순서대로 사용하는 시험용 보스.
- 앞의 두 구간을 정리하면 무작위로 제시된 강화 3개 중 1개를 선택합니다.
- 보스 처치 후 오른쪽 출구에서 E를 누르면 클리어합니다.
- 사망하면 체력·강화·진행은 초기화됩니다. 누적 사망 횟수만 로컬 PlayerPrefs에 남습니다.
- 방 구성과 적 배치는 고정입니다. 강화 선택지와 배경 장식만 시드에 따라 달라집니다. 절차 생성 던전은 아직 없습니다.

## 전투 읽기

- **주황색:** 공격 전조. 적이 공격 방향을 고정합니다.
- **빨간색:** 공격 활성 구간.
- **보라색:** 공격 후 회복 구간. 반격 기회입니다.
- 가까운 돌진은 통과 대시나 점프로 피하고, 원거리 공격은 발판·점프·대시로 피합니다.
- 보스의 넓고 낮은 주황색 띠는 지면 파동 전조입니다. 붉게 바뀌기 전에 점프합니다.
- 적과 몸이 닿는 것만으로 피해를 주지 않습니다. 활성 공격과 투사체만 피해를 줍니다.
- 피격 후 0.8초 보호가 있습니다. 사망 화면에는 마지막으로 맞은 공격의 대응 힌트가 표시됩니다.

## 대시 수치 — 테스트용 가정

패링은 구현하지 않았습니다.

- 대시 지속·무적: 0.14초, 속도 23 유닛/초.
- 이전 대시 시작에서 0.38초 이내 입력은 연속 대시로 계산합니다.
- 2번째 연속 대시가 시작되면 그 시점부터 0.5초 동안 추가 대시를 제한합니다.
- 충분히 간격을 두고 입력하면 연속 횟수가 초기화됩니다.
- 제한 중에도 이동·점프·공격은 가능합니다. 대시 애니메이션 중에는 대시 이동을 우선합니다.

수치는 기획서의 미정 항목을 실행 가능하도록 임시 설정한 것이며 최종 결정이 아닙니다.

## 확정 방향과 임시 선택의 구분

기획서에서 채택한 방향은 횡스크롤 이동, 지상·공중 무적 대시, 연속 대시 제한, 패링 없음, 전조를 읽는 전투입니다.

`Storyborn`이라는 작업명, 근접 공격, 세 전투 구간, 적과 보스의 명칭·패턴, 강화·진행·사망 규칙은 **이번 프로토타입을 위한 임시 선택**입니다. 기획서에 등장하는 세계관 예시를 정식 캐릭터로 확정하지 않았습니다. 주인공 정체, 메인 스토리, 기억·망각의 세계 법칙을 게임 시스템으로 확정하지 않았습니다.

## 파일 구조와 이후 작업

- `Assets/Scripts/StoryGame.cs`: 진행, 플레이어, 시험 적, 투사체, 임시 렌더링, UI.
- `Assets/Scripts/CombatRules.cs`: 엔진과 독립적인 대시 횟수·공격 범위·겹침 규칙.
- `Assets/Editor/PrototypeSetup.cs`: 씬 열기, 규칙 점검, Windows 빌드 메뉴.
- `Validation/`: 실제 규칙 코드를 사용하는 .NET 검사 프로그램.
- `VALIDATION_KO.md`: 수행한 검증과 남은 확인 항목.

현재는 조작감을 빠르게 바꾸기 위한 단일 런타임 중심 구조입니다. 이미지 제작 단계에서는 `Box()`로 생성한 SpriteRenderer의 스프라이트와 `SyncVisuals()`를 교체하면 됩니다. 이후 정식 제작에서는 플레이어·적·방·UI를 각각의 컴포넌트와 프리팹으로 분리하는 것이 좋습니다.

## 빌드

Unity Hub에서 해당 에디터의 **Windows Build Support**를 설치한 뒤 `Storyborn → Build Windows x64`로 빌드 폴더를 선택합니다. 또는 Unity Build Settings에서 `Prototype` 씬을 사용합니다. **이번 제공물은 Unity 소스 프로젝트이며 실행 파일은 포함하지 않습니다.**

## 알려진 제한

전용 이미지·애니메이션·음악·효과음, 저장된 런 이어하기, 게임패드·모바일 조작, 정식 스토리, 메타 성장, 절차 생성 맵은 아직 없습니다. UI는 기본 폰트를 사용하는 영문이며, 이 안내서는 한국어입니다. 좁은 화면에서는 16:9 Game 뷰를 사용해 주세요. 임시 지형 충돌은 바닥과 단방향 발판만 처리하며 복잡한 Tilemap 지형에는 별도 작업이 필요합니다.
